# HeatLab — розподілений розрахунок теплопровідності пластини

Користувач задає квадратну пластину N×N, кількість ітерацій K і температури чотирьох країв. Сервер рахує, як розподілиться тепло (рівняння Лапласа, метод Якобі). Обчислення розподілені між кількома серверами застосувань; балансувальник віддає кожну задачу вільному серверу.

**Стек:** C# / .NET 8, ASP.NET Core, EF Core + SQLite, HTML + JavaScript без фреймворків.

## Запуск

Потрібен лише [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

```text
run.bat          звичайний запуск
run.bat fresh    почати з порожньої бази даних
```

У VS Code сайт можна запустити кнопкою **Run** (F5): конфігурація «HeatLab — запустити сайт» зупиняє стару копію, збирає проєкт і відкриває браузер. Зупинка — Shift+F5.

Вікно `run.bat` — це **шлюз з балансувальником**. Він відкриває <https://localhost:7443> і сам запускає у фоні сервери застосувань `server-1` і `server-2` (без окремих вікон; їхні логи й рішення балансувальника видно у вікні шлюзу).
Сертифікат самопідписаний, тому в браузері треба натиснути «Додатково» → «Перейти на localhost».
Щоб зупинити систему, закрийте вікно шлюзу. Сервери вимкнуться разом із ним.

| Сторінка | Адреса |
| :--- | :--- |
| Сайт | <https://localhost:7443> |
| Адмін-панель | <https://localhost:7443/admin.html> — `admin` / `admin123` |

## Як це працює

```text
                 HTTPS
  Браузер ───────────────▶ ШЛЮЗ :7443 = веб-сервер + load balancer
                           (сторінки, вхід, історія, адмінка)
                                │  POST /run/{id} — тільки вільному серверу
               ┌────────────┬───┴────────┬────────────┐
               ▼            ▼            ▼            ▼
           server-1     server-2     server-3     server-4     ← рахують задачі
            :5101        :5102        :5103        :5104          (3 і 4 — автоматично)
               └────────────┴─────┬──────┴────────────┘
                                  ▼
                    SQLite storage/heatlab.sqlite  ← прогрес і результати
```

1. Браузер звертається тільки до **шлюзу**. Шлюз сам обробляє вхід, історію, скасування й адмінку.
2. Нова задача записується в БД, і **балансувальник** вибирає сервер за зайнятістю (без Round Robin):
   - `server-1` вільний → задача йде на `server-1`;
   - `server-1` зайнятий → задача йде на `server-2`;
   - усі зайняті → запускається новий сервер (до 4), задача чекає в черзі з позицією й часом очікування;
   - черга заповнена (4 задачі) → **відмова у виконанні**.
3. Сервер застосувань рахує задачу й сам пише в БД прогрес (кожні 0.5 с) і результат.
4. Звільнився сервер — балансувальник одразу віддає йому наступну задачу з черги. Додатковий сервер, що простоює 30 с, вимикається.

## Вимоги завдання

| # | Вимога | Як зроблено |
| :--- | :--- | :--- |
| 1 | Обмеження трудомісткості | N ≤ 1000, K ≤ 50 000, **N·N·K ≤ 2·10¹⁰**, ліміт часу 120 с. Перевірка на клієнті ([app.js](frontend/js/app.js)) і на сервері ([HeatSolver.cs](src/HeatLab/Solver/HeatSolver.cs)) |
| 2 | Інформування про хід виконання | Прогрес у % і номер ітерації, оновлення щосекунди |
| 3 | Історія, стан, скасування, нова задача; ліміт задач; БД | Таблиця «Мої задачі»: скасувати / показати / видалити; ≤ 5 активних, ≤ 50 в історії; SQLite |
| 4 | Авторизація + HTTPS | Реєстрація/вхід, PBKDF2, cookie `HttpOnly` + `Secure`, ролі; HTTPS, HTTP → HTTPS 301, HSTS |
| 5 | Балансування ≥ 2 серверів | Шлюз — load balancer ([Balancer.cs](src/HeatLab/Gateway/Balancer.cs)), задачі рахують окремі процеси server-1, server-2 і пишуть у БД. Перший зайнятий → на другий |
| 6 | Черга + приблизний час очікування | «Усі сервери зайняті — задачу поставлено в чергу: позиція p, очікування ~N с»; черга повна → відмова |
| 7 | Горизонтальне масштабування з лімітом | Автоматичний запуск server-3, server-4 (максимум 4), вимкнення після 30 с простою |
| 8 | Панель адміністратора | Процеси (PID), стан серверів, навантаження %, черга, усі задачі зі скасуванням |

## Як продемонструвати

Задачі N = 600, K = 50 000 рахуються ~30 с:

1. Перша задача → `server-1`, друга → `server-2` («перший зайнятий — на другий»).
2. Третя → «МАСШТАБУВАННЯ ВГОРУ», запускається `server-3`; четверта → `server-4`.
3. П'ята → «поставлено в чергу» з позицією та часом очікування; шоста → «У вас уже 5 активних задач».
4. Другий користувач (вікно інкогніто) заповнює чергу ще трьома задачами, четверта → «Відмова у виконанні: усі сервери зайняті, а черга заповнена».
5. Адмінка: 4 сервери рахують, навантаження 100 %. Через 30 с після завершення `server-3` і `server-4` вимкнуться.

Детальний сценарій — у [docs/DOCUMENTATION.md](docs/DOCUMENTATION.md#16-як-показати-викладачу).

## Структура

```text
src/HeatLab/
  Program.cs             – вибір ролі: шлюз або сервер застосувань
  Limits.cs              – усі обмеження
  Solver/HeatSolver.cs   – параметри, перевірка, метод Якобі
  Data/                  – таблиці БД, підключення, скасування і черга
  Gateway/               – HTTPS і сайт (GatewayApp), балансувальник і масштабування (Balancer), API
  Server/ServerApp.cs    – сервер застосувань: обчислення
frontend/                – login.html, index.html, admin.html, css/, js/
tests/HeatLab.Tests/     – автоматичні тести
docs/DOCUMENTATION.md    – повна технічна документація
docs/ARCHITECTURE.puml   – UML-діаграми архітектури (PlantUML)
docs/DEFENSE_QA.md       – питання на захисті з відповідями
```
